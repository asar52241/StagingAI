# Решено: ошибка 29 у Робокассы при передаче Receipt

## Итог

Причина найдена и исправлена. **`Receipt` не должен входить в базу для расчёта `SignatureValue`**,
хотя официальная документация Робокассы (`docs.robokassa.ru`) описывает формулу с ним:
`MerchantLogin:OutSum:InvId:Receipt:Пароль#1`. У магазина `StagingAI` эта формула отклоняется
с ошибкой 29 («неверный SignatureValue») — даже с дословным Receipt-примером из документации.
Рабочая формула — без Receipt: `MerchantLogin:OutSum:InvId:Пароль#1`, при этом сам параметр
`Receipt` в query-строке остаётся (чек по-прежнему формируется).

Исправлено в `lib/robokassa.ts` (`buildPaymentUrl`) — `sig` считается без `receiptEncoded`
в любом случае.

## Что подтверждено рабочим

1. **Формула подписи без Receipt.** `md5(login:outSum:invId:пароль)` — принимается Робокассой,
   демо-форма открывается, тестовая карта `4111 1111 1111 1111` проходит.
2. **Та же формула + Receipt в query (не в подписи).** Тоже принимается — чек передаётся,
   ошибки 29 нет.
3. **Формула с Receipt в подписи (по документации)** — всегда ошибка 29, вне зависимости от
   содержимого Receipt (свой JSON или пример 1:1 из документации).

## Диагностика, которая привела к решению

- Пересоздание тестовых паролей в кабинете — не помогло (ошибка не в паролях)
- Проверка алгоритма хеша (MD5) в кабинете — совпадает с кодом
- Добавление `Email` к запросу — не помогло
- Использование дословного примера Receipt из документации — та же ошибка
- Бинарный тест: запрос без Receipt (успех) vs с Receipt в подписи (ошибка) vs с Receipt
  в query, но без Receipt в подписи (успех) — изолировал причину именно в составе подписи

## Попутно исправлено

`lib/robokassa.ts` — `Receipt` кодировался в URL **дважды** (`encodeURIComponent()` внутри +
повторное кодирование через `URLSearchParams.set()`/`new URL()`). Исправлено: `Receipt`,
`SuccessURL`, `FailURL` дописываются в query-строку напрямую, без повторной сериализации
через `URLSearchParams`.

## Статус

Закрыто. Сквозная оплата (подпись → редирект → квота в `lib/orders.ts`) проверена рабочей
end-to-end в тестовом режиме.
